# المرحلة 1 (المنتج الجديد): تقرير اختبار يومي مختصر ومراجعة المطور

الفرع: `feature/improve-daily-testing` — مبني على `main` (`8e30831`).

## ما تغيّر

**المختبر**
- بطاقة «اختبار اليوم» في أعلى الرئيسية لأول تطبيق مطلوب اليوم، ونفس البطاقة في شاشة التقرير: اسم التطبيق، «اليوم N من 14»، مهمة اليوم، زر «فتح التطبيق»، سؤال «شلون كانت التجربة؟» بثلاثة خيارات، حقل «شنو جرّبت؟»، وزر «إرسال التقرير».
- حُذف مربعا التأكيد السابقان (فتحت التطبيق / نفذت المهمة)؛ لا نسخ أو تنزيل أو لقطات إلزامية.
- بعد الحفظ تظهر حالة التقرير المحفوظ (النتيجة، الملاحظة، حالة المراجعة) بدل نموذج جديد. إذا طلب المطور توضيحاً يظهر تنبيه وزر المحادثة.
- زر «فتح التطبيق» يفتح صفحة التطبيق في Google Play (أو رابط الانضمام إذا لم يُعرف اسم الحزمة). فتحه لا يُحتسب تقريراً.

**المطور** (تفاصيل التطبيق ← تقارير المختبرين)
- لكل تقرير: اسم المختبر، التطبيق، رقم اليوم، المهمة، النتيجة، الملاحظة، وقت الإرسال، حالة المراجعة.
- أزرار: «قبول التقرير»، «طلب توضيح» (يرسل رسالة للمختبر في نفس العملية)، «رفض التقرير».

## Firestore — إضافات فقط، بلا Migration

- نفس المجموعة `reports` ونفس المعرّف `{assignmentId}_{YYYY-MM-DD}` ونفس المعاملة الذرية مع `assignments.checkins` و`lastCheckinAt` ورسالة للمطور.
- قيمة نتيجة جديدة `outcome: 'blocked'` (ما گدرت أكمل) إلى جانب `ok` و`issue`. تُحفظ بـ `status: 'new'` مثل `issue` حتى تظهر كمشكلة مفتوحة.
- حقول مراجعة اختيارية: `reviewStatus` (`accepted` | `clarify` | `rejected`)، `reviewedAt` (وقت الخادم)، `reviewerUid`. غيابها يعني «بانتظار المراجعة»؛ التقارير القديمة تعمل كما هي.
- لم تتغير قواعد العدّ: اليوم يُحسب من `joinedDay` بتوقيت UTC، ونافذة 14 ساعة بين التقارير، والحد 14 تقريراً.
- لا فهارس جديدة. استعلام عدّ المشاكل للحساب المزدوج صار `ownerUid + status=='new'` (مساواة فقط).

## تغييرات القواعد (`firestore.rules`)

- إنشاء التقرير: قبول `blocked` مع إلزام `status: 'new'`. قائمة الحقول المسموحة عند الإنشاء لم تتغير، فلا يستطيع المختبر وضع مراجعة لتقريره.
- تحديث التقرير: صاحب التطبيق فقط، ومشروع غير مؤرشف/قيد الحذف، وأحد مسارين:
  1. إغلاق مشكلة (`issue` أو `blocked`) بتغيير `status` إلى `fixed` فقط (كما كان، مع إضافة `blocked`).
  2. مراجعة تغيّر `reviewStatus/reviewedAt/reviewerUid` فقط، بوقت الخادم وهوية المراجع.
- لا يمكن لأي مسار تعديل `notes` أو `outcome` أو `tested` أو `date` أو التوقيتات.

## قبل الدمج والنشر (يحتاج موافقة المالك)

1. تأكد من نجاح Actions على الـ PR، خصوصاً `npm run test:rules`.
2. انشر القواعد أولاً: `npx firebase deploy --only firestore:rules --project testhubiq-c7711`. الواجهة الجديدة ترسل `blocked` والمراجعات، والقواعد القديمة سترفضها.
3. بعدها ادمج وانشر الاستضافة (`testiqx`)، ثم جرّب بحسابي مطور ومختبر حقيقيين.

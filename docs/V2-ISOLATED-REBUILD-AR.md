# TesterHub V2 — خطة إعادة البناء بمعاينة منفصلة (2026-11-11)

## الحالة
**مخطط ومعاينة واجهة فقط؛ ليست منصة V2 جاهزة للإنتاج أو منشورة.**
الفرع: `feature/v2-isolated-preview-20261111`، مستقل عن `main` وعن `feature/exchange-groups-pilot-20261111`. لا تعديل على أي مستند Firestore ولا قواعد أو فهارس أو استضافة إنتاجية.

## قرار المنتج
1. شريط تنقل سفلي RTL بأربعة أقسام فقط: **التطبيقات**، **مجموعات التبادل**، **اختباراتي**، **حسابي**.
2. **التطبيقات:** بحث، بطاقات عمودية صغيرة (أيقونة، اسم، مطور، مكافأة XP موثقة، حالة التوفر)، صفحة التفاصيل (وصف، تعليمات الاختبار، رابط اشتراك Play، رابط المجتمع/Google Group عند توفره)، نموذج إضافة تطبيق (أيقونة، اسم، مطور، رابط Play، وصف، تعليمات، بدون رابط مجموعة داخل نموذج إضافة التطبيق؛ رابط اختبار Google Play فقط). يحتفظ النظام بحد **تطبيق واحد مجاني للمطور**؛ لا تعتمد أي مكافأة لمجرد الضغط.
3. **المجموعات:** عرض عضوية مجتمع المختبرين وشروطه، ثم مجموعات التبادل ذات 15 مقعداً ومهام أعضائها عند دمج PR الخاص بها. لا تخلط مجموعات الـ15 بالمجموعة الرسمية العامة.
4. **اختباراتي:** الاختبارات المنضم إليها + تقدم اليوم + تقارير الاختبار الفعلية + الإبلاغ عن عطل والتواصل مع المطور، مع الاستفادة من السجلات والـ UIDs القائمة.
5. **حسابي:** الملف الشخصي، تطبيقاتي، XP الموثقة، الرسائل، الإعدادات، الدعم، سياسة الخصوصية والبيانات.

## قرارات التصميم بعد مراجعة المعاينة
- احتفظ بهوية TesterHub الأصلية (الأزرق والأبيض والأخضر، والخط والشعار)، ولا تستنسخ ألوان المنافس.
- **إضافة التطبيق**: اسم، مطور، أيقونة، رابط اختبار Google Play واحد، وصف، تعليمات. إلغاء إدخال رابط المجموعة على مستوى التطبيق؛ الرابط الرسمي يُدار مركزياً.
- **حسابي**: صورة شخصية واسم عام قابلان للتعديل، بريد غير قابل للتحرير من دون مسار تحقق هوية، سمعة ونقاط XP موثقة، إحصاءات المشاركة، إعدادات الخصوصية والدعم. لا تُدخل Moons أو خطط مدفوعة لمجرد وجودها في مرجع بصري.
- **بطاقات مجموعات التبادل**: غلاف يحمل اسم المجموعة وعدد المقاعد، وشبكة **15** أيقونة للتطبيقات المنضمة، وأسماء التطبيقات وتفاصيلها عند الضغط، ثم رحلة الاختبار وقواعد الالتزام والتذكير.
- **تغذية الصور الفعلية عند الربط**: كل عضو داخل `exchangeGroups/{groupId}/members/{uid}` مرتبط بمشروعه المعتمد `projects/{projectId}` أو بمعرف تطبيق قائم دون مضاعفة سجلات المشروع؛ أيقونة التطبيق تُقرأ من سجل المشروع/رابط الصورة المصرح به، وتعرض placeholder عند غيابها. بيانات أعضاء المجموعة تُحمّل للمخولين فقط، مع حدود استعلامات مناسبة لخطة Spark. **المعاينة الحالية لا تعرض صور الأعضاء الحقيقية؛ إنها بيانات محلية توضيحية.**
- لا تغيّر تعداد المجموعات الحالي (15) أو قواعد الإنذارات المبنية في PR #47 حتى تتم مراجعة فرع التكامل.

## سياسة المرور بعد التسجيل
- بعد اكتمال إنشاء حساب Firebase Auth والملف الشخصي والشروط، تظهر شاشة الانضمام إلى **المجموعة العامة للمختبرين** مرة واحدة قبل استخدام المحتوى المحمي.
- فتح رابط Google Group (مثل `https://groups.google.com/g/testerhubiq`) من الواجهة هو انتقال خارجي، **لا إثبات عضوية**. لا توثق المنصة العضوية آلياً دون تكامل تحقق مع Google وإذن مناسب؛ الإقرار الشخصي يوصف صراحة بأنه غير متحقق.
- الانضمام للمجموعة العامة **لا يسجل العضو تلقائياً في كل اختبارات Google Play**. يجب أن يضيف كل مطور المجموعة/حسابات المختبرين إلى مسار اختباره في Play Console، ويجب على المختبر فتح رابط opt-in الخاص بكل تطبيق والتسجيل فيه بحساب Google المؤهل. بعد هذا يمكن البدء باختبار التطبيق وتقديم تقارير.
- لا تُفعّل مكافأة XP إلا حسب شروط تقرير/نشاط موجودة ومراجعة على الخادم. لا تساوِ بين فتح الرابط والاختبار المكتمل.
- لا يُطبّق شرط الانضمام الجديد على الإنتاج حتى تستكمل آلية التحقق/الإقرار الآمنة وسياسة الخصوصية وتوافق المستخدمين القدامى. من فقد الوصول للمجموعة تبقى له إمكانية تسجيل الخروج، إعدادات الحساب، الدعم، واستعادة بياناته.

## فصل البيئة والبيانات
- **الكود:** فرع مستقل ومعاينة `preview/v2/index.html` ببيانات توضيحية محلية، بلا Firebase، فلا يقرأ ولا يكتب أي بيانات إنتاج.
- **الاستضافة اللاحقة:** قناة Firebase Hosting preview مستقلة خاصة بالهدف القائم `testiqx`، مثل `v2-preview`، دون `firebase deploy` المعتاد أو نشر قواعد Firestore أو استخدام رابط الإنتاج. نشر preview يحتاج صلاحيات CI محفوظة في GitHub Secrets، وليس مفاتيح ضمن المستودع.
- **الاختبار الخلفي:** استخدم Firebase Emulator مع fixtures منفصلة أو مساحة بيانات اختبار معزولة ومصرح بها؛ **لا تستخدم بيانات إنتاج حقيقية للاختبارات الكتابية**. على مشروع Firebase نفسه، رابط Hosting مختلف لا يعزل Firestore/Auth تلقائياً.
- يحتفظ الإنتاج الحالي على `main` وبنفس البيانات دون لمس. النسخة الجديدة تستعمل نفس `UID` ومعرّفات `projects/assignments/reports` بعد تحديد التوافق، لا إعادة إنشاء التطبيقات.

## خطة التنفيذ المقترحة
1. **V2 Preview UI:** معاينة بأربعة تبويبات، شاشة التسجيل/الانضمام، نموذج إضافة التطبيق، البطاقات، التفاصيل، اختباراتي وحسابي، كلها محلية للتصميم فقط.
2. **Adapter للبيانات:** قراءة مستندات التطبيقات الحالية مع توافق الحقول القديمة، pagination وفهارس مناسبة، placeholder لأيقونات قديمة؛ كتابة تزايدية backward compatible فقط بعد اختبار Rules/Emulator.
3. **ربط المجموعات:** مراجعة PR #47 وفرع المجموعة التجريبي. المعمارية المعتمدة لـV2 تفصل بين **المجتمع العام المجاني الإلزامي** و**Packs التبادل ذات 16 مطوراً والمقعد المدفوع بـ100 Hub Coins** و**التطبيقات العامة**. مجموعات V2 تحتوي مشاريعها وأيقوناتها وبياناتها الخاصة، من دون نشرها تلقائياً في الصفحة الرئيسية. واجهة Packs لها «متاحة» و«مجموعاتي»، وتسمح بمجموعتين مفتوحتين بالتزامن عند ارتفاع الطلب، وتنقل المجموعة المكتملة إلى «مجموعاتي» للأعضاء فقط. تغيير سعة PR #47 من 15 إلى 16 يحتاج تعديلاً صريحاً للقواعد والاختبارات وحفظاً للمجموعات القديمة.
4. **مهام الاختبار:** القائمة الخاصة بكل مستخدم حسب حالة opt-in والتعيين في البيانات، ورفع التقارير/البلاغات، منع مضاعفة XP والتأكيدات بالـtransaction/rules.
5. **مراجعة الأمان:** Firestore rules, indexes, privacy, permissions, anti-abuse, backward compatibility, read quota, consent.
6. **QA:** `npm test`, `npm run test:rules`, `npm run test:e2e`, `npm run build`، ثم أجهزة Android حقيقية وحسابات متعددة. فحص استعادة البيانات وroll-back. اختبار المستخدم الجديد والقديم، عضو المجموعة وغير العضو، التطبيق القديم والجديد، اتصال ضعيف، نقص الصلاحيات، والتقرير اليومي.
7. **نشر تدريجي:** معاينة مستقلة أولاً، وبعد موافقة صريحة فقط يُحدّد merge إلى `main` ونشر الواجهة الجديدة. احتفظ بفرع/بناء الإصدار السابق للرجوع السريع؛ ترحيل البيانات (إن لزم) يكون additive ومراجَع ونسخة احتياطية معتمدة.

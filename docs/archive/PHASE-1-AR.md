# المرحلة الأولى — الحسابات والأساس الأمني

## النطاق والحالة

العمل على المستودع الحالي، من commit `dd84d5179496afec2b7a428b1a940d3064076c60`، في الفرع `phase-1/accounts-security`. لا يوجد مشروع بديل. هذه مرحلة أساس تقني وليست إعلان جاهزية المنصة الكاملة.

المستخدم أكد أن الحسابات القديمة حساباته التجريبية وأجاز تعديل قواعد الإنتاج بعد الاختبارات. لم نحتج حذف أي حساب أو تقرير أو تغيير UID. لا توجد صلاحية Firebase إدارية في بيئة التنفيذ: `firebase projects:list --non-interactive` يفشل برسالة مصادقة. لذلك لم يتم نشر قواعد أو دمج تحديث الواجهة.

## الوضع السابق والمشكلات المثبتة من الكود

- تطبيق HTML/CSS/JS واحد غالبية المنطق في index.html، وFirebase Web SDK محمّل من CDN.
- users: ملف الحساب والدور والاسم والبريد والموافقة available. projects: تطبيق يملكه المطور. assignments: ربط المطور بالمختبر والتقدم. reports: تقرير مرتبط بتكليف ويوم. messages: رسائل أطراف التكليف.
- تسجيل ودخول وخروج موجودة؛ لا تأكيد بريد ولا استرجاع كلمة مرور ولا تعديل اسم.
- إنشاء Auth ثم فشل كتابة users يترك حساباً بلا ملف ولا مسار لإكماله.
- الصلاحيات لا تفرض تأكيد البريد. قواعد profiles تسمح بتعديل available فقط.
- موافقة مشاركة البريد محددة مسبقاً في التسجيل.
- 44 اختباراً سابقاً: معظمها عقود نصية، وبعضها يشغّل دوال مقتطعة. لا Emulator أو PR CI.
- Pages ينشر جذر المستودع؛ إضافة أدوات اختبار تستدعي استبعاد node_modules من النشر.

## المنفذ

- src/services/accounts.js: خدمة حسابات منفصلة عن DOM، بالاعتماد المحقون على Firebase.
- إنشاء الحساب مع تحقق الاسم والدور قبل Auth. استرداد الملف المفقود بنفس UID عبر Transaction لا تستبدل ملفاً موجوداً.
- تأكيد البريد: زر إرسال، إعادة تحميل حالة Auth وتجديد ID token؛ حجب لوحة الحساب إلى حين التأكيد.
- استرجاع كلمة مرور برد محايد عن وجود الحساب، رسائل أخطاء عربية.
- تعديل اسم المطور والمختبر، إخفاء البريد، إيقاف استقبال مشاركات جديدة. الإيقاف لا يوقف عداد مشاركة جارية ولا يعدل سجلاتها.
- تصنيف المشاركات الحالية والسابقة في شاشة الاختبارات.
- الموافقة على مشاركة البريد اختيار صريح غير محدد مسبقاً للحسابات الجديدة؛ الموافقات القديمة تبقى كما هي.
- تنظيف بيانات الشاشة والمستمعين عند خروج الحساب أو تبديل الحساب من نافذة أخرى، وحماية refresh من بيانات جلسة سابقة.
- مسار إعادة المحاولة والخروج عند فشل بدء التطبيق.
- Cache جديد مع حصر التخزين في ملفات الواجهة، وحفظ وحدة الحسابات للتشغيل اللاحق.
- حزمة نشر allowlist في dist؛ لا تنشر الاختبارات أو الأدوات أو سجلات Emulator.
- PR CI، اختبارات Firebase محلية، واختبارات متصفح بقياسين.

## تغييرات Firestore

لا مجموعات جديدة ولا Migration تمس البيانات. الحقل الاختياري الوحيد `users.participationPaused` (boolean)؛ غيابه يعني غير موقوف. قواعد التحديث تسمح فقط بالاسم وavailable وparticipationPaused، وتمنع تعديل الدور والبريد أو إضافة UID/صلاحيات. الإيقاف يتطلب available=false.

قراءة الملف الخاص تبقى متاحة حتى قبل تأكيد البريد لإكمال الحساب. قراءة دليل المختبرين وإنشاء تطبيق/تكليف تتطلب مطوراً مؤكّد البريد. بدء الاختبار وكتابة التقارير والرسائل وتحديث حالة البلاغ تتطلب تأكيد البريد. قراءات الأطراف القديمة تبقى معزولة بينهم. لا Admin self-registration.

لا تغيير للفهارس الحالية. لا نشر تلقائي لقواعد Firebase ضمن Actions.

## النشر والمتطلبات اليدوية

1. راجع PR واختبارات Actions؛ لا تدمج قبل نشر القواعد المتوافقة.
2. من جهاز له وصول إلى مشروع Firebase الحالي: `firebase login` (لا ترسل بيانات اعتماد في المحادثة أو Git).
3. احفظ نسخة القواعد المنشورة حالياً، وتأكد من project ID وEmail/Password وAuthorized domains وtemplates العربية.
4. شغّل `npm ci && npm test && npm run test:rules`.
5. انشر القواعد المراجعة فقط: `npx firebase deploy --only firestore:rules --project testhubiq-c7711`.
6. ادمج PR، انتظر نجاح Pages، ثم اختبر حساب مطور ومختبر تجريبيين وتأكيد البريد على الموقع.
7. لا تعد نشر قواعد أقدم عند التراجع بلا مراجعة؛ الرجوع للواجهة القديمة لا يلغي شرط تأكيد البريد الجديد.

الموقع: https://alaaajeel.github.io/testerhub/ . لم يُنشر هذا التحديث ولا تُعد النسخة الحالية محتوية عليه.

## البنية التدريجية

لا إعادة كتابة ولا bundler للمنتج. استخرج الخدمات أولاً ثم العرض تدريجياً: auth/profiles (تم)، projects/assignments، reports/bugs، messaging/notifications، admin، ثم UI components ولوحتي المطور والمختبر. تبقى API adapter القديمة لتجنب كسر الشاشات خلال الاستخراج.

## التكلفة

لا Cloud Functions أو خدمة مدفوعة أضيفت. الحقل الجديد بنفس المستند. قراءة الملف من الخادم تمنع اعتبار ملف مخزن محلياً مرجعاً لحالة الحساب، لكنها تزيد اعتماد الحساب على الاتصال. الاستعلامات والمستمعون السابقون ما زالوا يحتاجون تقليل تكرار وتحميل تدريجي في مرحلة الأداء. لا يمكن تقدير فاتورة فعلية دون أعداد النشاط وقياسات Console. يوصى بتنبيهات الميزانية والاستهلاك قبل توسعة الجمهور؛ لم يتم ضبط أي تنبيه على المشروع.

## المتبقي والجاهزية

المرحلة الأولى جاهزة للمراجعة والاختبار المرحلي، وليست إطلاق MVP. تظل مشكلة التواريخ المعتمدة على الجهاز ونافذة 14 ساعة، الدعوات للجميع، نقص حالات المشاريع والدعوات وبلاغات الأخطاء والإشعارات المقروءة وAdmin والخصوصية والتكلفة الشاملة للمراحل التالية. النتيجة لا تدّعي إصلاحها.

# المرحلة الثانية: مسودات المشاريع ونشر الدعوات

فرع التنفيذ: `phase-2/project-lifecycle`، مستقل عن فرع اختيار المختبرين الذي دُمج سابقاً.

## المنفذ

- إنشاء مسودة باسم التطبيق ورابط اختياري دون دعوات أو تكليفات، مع تعديلها قبل النشر.
- نشر المسودة بإيميلات المختبرين المختارين صراحة؛ يحفظ انتقال `draft → recruiting` ثم ينشئ التكليفات الناقصة فقط. في حال فشل الدعوات تظهر رسالة إصلاح ولا تُحذف المسودة المنشورة أو أي تقدم.
- منع إرسال تكليف قبل النشر، ومنع تغيير الاسم والرابط والقائمة المختارة بعد النشر في قواعد Firestore. المشاريع القديمة من دون `status` تبقى مقروءة ومسموحاً بإصلاح دعواتها المختارة وفق القواعد السابقة.
- لا يجري حذف أو Migration لبيانات الإنتاج.

## التحقق

- `npm test`: 55 ناجحاً.
- `npm run test:rules`: 16 ناجحاً في محاكي Auth وFirestore، ومنها انتقال المسودة، منع مطور آخر، منع تكليف مبكر، منع تغيير مشروع منشور وروابط غير رسمية.
- `npm run test:e2e`: 12 ناجحة في محاكاة المتصفح للهاتف وسطح المكتب.
- `npm run build` و`npm run preflight`: ناجحان.

## شرط الإطلاق

يجب نشر `firestore.rules` من هذا الفرع **قبل** دمج واجهة المسودات أو نشرها في GitHub Pages. النشر يحتاج جلسة Firebase Console بصلاحية المشروع أو هوية Firebase CLI مخولة. لا تثبت اختبارات المحاكي أن القواعد نُشرت فعلياً. إذا لم يتوفر التحقق من قواعد الإنتاج، أبقِ Pull Request مفتوحاً.

## الباقي من المرحلة الثانية

حالات دعوة مقبولة/مرفوضة/منتهية، انتقالات Active/Completed/Archived مع سجل تغييرات، والوقت المعتمد على الخادم لتقارير 14 يوماً. لا تعني `recruiting` قبول المختبر أو اشتراك Google Play الرسمي.
